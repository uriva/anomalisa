anomalisa docs

Install

npm i anomalisa

Or with Deno:

deno add npm:anomalisa

Then import in Node, Deno, Bun, or browsers:

import { sendEvent, getAnomalies } from "anomalisa";

sendEvent

Records an event. The server builds a statistical model from your events and emails you when something looks anomalous.

await sendEvent({ token: "your-project-token", userId: "user-123", eventName: "purchase", });
Field Type Description
token string Your project token from the dashboard
userId string Identifies the user performing the action
eventName string Name of the event (e.g. "signup", "purchase")

Returns an empty object. Anomaly detection and alerting happen server-side.

getAnomalies

Fetches all detected anomalies for a project. Anomalies are kept for 30 days.

const { anomalies } = await getAnomalies({ token: "your-project-token" });

Each anomaly has:

Field Type Description
eventName string The event that spiked
metric "totalCount" | "userSpike" | "percentageSpike" | "percentageDrop" Type of anomaly detected
userId string? Present when metric is "userSpike"
bucket string The hourly bucket (ISO timestamp)
expected number Running mean for this event
actual number Observed count in this bucket
zScore number Standard deviations from mean (overdispersed totalCount, userSpike), -log10(p) (Poisson totalCount), or fractional change (percentageSpike, percentageDrop)
detectedAt string ISO timestamp of detection

How detection works

Events are counted in hourly UTC buckets (YYYY-MM-DDTHH). The server maintains a decaying Welford's online algorithm baseline per event with statsDecay = 0.98, minDataPoints = 3, and minColdStartCount = 5. Four metrics are tracked independently:

Total count (totalCount) -- Uses a two-sided Poisson test (p < 1e-3) when variance is near-Poisson, falling back to 3σ (zScoreThreshold = 3) when overdispersed (stdDev > max(1, sqrt(mean))). Also includes cold-start burst detection (count >= 5 when n < 3), live mid-hour spike checks, and per-hour-of-day (byHour:<HH>) seasonality.

Percentage spike (percentageSpike) -- Fires when an hourly count is >100% above the rolling mean (diff >= 3, mean >= 10, z >= 2.5) and is not explained by byHour:<HH> seasonality.

Percentage drop (percentageDrop) -- Fires on a single-hour >50% drop (mean >= 30, diff >= 3, z >= 1.05) or a rolling 2h/6h/24h drop compared to the prior 3-6 days (z >= 2.5; skipped for error/failure events).

Per-user spikes (userSpike) -- Tracks max_user_counts (the highest single-user count per hourly bucket) into a per-event "perUser" Welford baseline (0.98 decay), and alerts when any single user's current-hour count exceeds it by > 3.5σ (minDataPoints = 3, count >= 3, and count >= 5 if 0 < mean < 1).

Self-hosting

Clone the repository, configure .env with your database, auth, and email credentials, and run the server with Deno:

# Required TURSO_DATABASE_URL=your-turso-database-url TURSO_AUTH_TOKEN=your-turso-auth-token INSTANTDB_APP_ID=your-instantdb-app-id INSTANTDB_ADMIN_TOKEN=your-instantdb-admin-token AGENTMAIL_API_KEY=your-agentmail-api-key # Optional (enables automatic GitHub issue triage) GEMINI_API_KEY=your-gemini-api-key

Push the InstantDB schema and permissions, then start the server:

npx instant-cli push schema --app $INSTANTDB_APP_ID --token $INSTANTDB_ADMIN_TOKEN npx instant-cli push perms --app $INSTANTDB_APP_ID --token $INSTANTDB_ADMIN_TOKEN deno run --allow-net --allow-env --allow-read src/server.ts
