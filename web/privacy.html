Privacy Policy

This Privacy Policy explains how anomalisa (anomalisa.uriv.me) collects, processes, stores, and deletes information when you visit our website, create an account, or send event telemetry to our anomaly detection API.

1. Information We Collect

  • Account and project data: your email address (for magic-code authentication and alert delivery), project names, generated project API tokens, and optional webhook URLs.
  • Event telemetry and anomaly data: event names, hourly event count buckets, statistical baselines, detected anomaly records, alert delivery logs/cooldowns, alert feedback ratings, and optional customer end-user identifiers (user_id) sent via the sendEvent API.
  • Optional GitHub integration credentials: if you enable GitHub issue creation from anomaly alerts, we store your configured repository identifier and GitHub Personal Access Token (PAT).
  • Usage analytics and error diagnostics: pageviews, product usage events, client exception reports, and server-side lifecycle events (such as signups, first event received, event submissions, and alert feedback), associated with your email address when signed in.

2. Infrastructure and Sub-Processors

  • InstantDB: provides magic-code email authentication and stores user accounts, projects, project API tokens, and webhook configurations.
  • Turso (libSQL): stores hourly event counts, running statistics, anomaly records, customer end-user user_id counts, outgoing alert email queues/cooldowns, and optional GitHub repository settings and Personal Access Tokens.
  • PostHog: provides client-side and server-side product analytics and exception capture, including calling identify with signed-in user email addresses.
  • AgentMail: sends transactional anomaly alert emails (including feedback and investigation links) and administrative notifications.
  • GitHub API: used only when you explicitly configure a GitHub Personal Access Token and trigger issue creation from an alert investigation link.
  • Cloudflare Workers: hosts the web pages, API endpoints, and scheduled anomaly-check and alert-delivery cron jobs.

3. B2B Processor Role and Customer End-User Data

When you integrate anomalisa into your own applications and transmit end-user identifiers (user_id) or event names, you act as the data controller for your end users and anomalisa acts as a service provider / data processor on your behalf. We strongly recommend sending pseudonymous or hashed user IDs rather than raw personal information (such as end-user emails, names, or sensitive data). You are solely responsible for providing appropriate privacy notices and obtaining any consents required from your end users.

4. Retention and Deletion

Hourly event buckets and expired tracking records are pruned periodically by automated cleanup jobs, while account, project, and configured integration records remain stored until deleted. You can remove GitHub credentials or projects in the dashboard, or request full deletion of your account, projects, Turso telemetry, and associated records at any time by contacting the operator via uriv.me with your account email address.

5. Security

We use HTTPS in transit and restrict access to project data via authentication and project tokens. Because GitHub Personal Access Tokens and project API tokens grant programmatic access, scope GitHub tokens to the minimum permissions required (such as Issues write on a single repository) and rotate them if exposed.

6. Changes and Contact

We may update this Privacy Policy as the service changes and will revise the Last Updated date above. For privacy questions or data deletion requests, contact the operator via uriv.me.
